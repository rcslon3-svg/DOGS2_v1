# DOGS² I²C Master Terminal

## Назначение

Модуль позволяет использовать DOGS² как I²C master и управлять внешними
I2C-устройствами из Bluetooth-терминала:

- искать устройства на шине;
- читать регистры;
- записывать регистры;
- выполнять чтение и запись без байта адреса регистра.

Режим работает на второй аппаратной I2C-шине ESP32.

| Параметр | Значение |
|---|---|
| Контроллер | `I2C_NUM_1` |
| SCL | GPIO26 |
| SDA | GPIO27 |
| Частота чтения и записи | 100 кГц |
| Уровень | 3,3 В |
| Адреса | 7-битные |

SCL и SDA должны иметь внешние pull-up резисторы к 3,3 В. Линии нельзя
подтягивать к 5 В.

## Файлы

- `src/i2c_master_terminal.c` — Bluetooth-команды, разбор строк, ответы и
  строки для дисплея.
- `include/i2c_master_terminal.h` — интерфейс terminal-модуля.
- `src/i2c_aux_bus.c` — владение I2C_NUM_1, scan, транзакции и recovery.
- `include/i2c_aux_bus.h` — интерфейс шины.

## Жизненный цикл

I2C_NUM_1 существует только в режиме `APP_MODE_I2C_MASTER`.

При входе в режим модуль:

1. захватывает GPIO26 и GPIO27;
2. создаёт `i2c_master_bus_handle_t`;
3. начинает принимать Bluetooth-команды.

При выходе из режима модуль:

1. запрещает приём новых I2C-команд;
2. очищает очередь и незавершённую строку;
3. дожидается окончания текущей короткой транзакции;
4. удаляет `i2c_master_bus_handle_t`;
5. возвращает GPIO26 и GPIO27 в режим входов.

Все операции с handle защищены одним mutex. Создание, удаление, recovery,
чтение и запись не могут выполняться одновременно.

## Ввод команд

Команда завершается одним из способов:

- символом `CR`;
- символом `LF`;
- паузой ввода не менее 200 мс.

Регистр и данные задаются шестнадцатеричными числами без `0x`. Регистр `0A`
означает десятичное значение 10. Параметр `len` задаётся десятичным числом.

Максимальный объём данных одной команды — 32 байта.

Разделителями могут быть пробелы, табуляция и запятые. Имена команд и
шестнадцатеричные цифры нечувствительны к регистру.

## Команды

### Поиск устройств

```text
S
```

Проверяются 7-битные адреса `0x03`–`0x77`. Для каждого адреса формируется
только address frame:

```text
START → address + W → ACK/NACK → STOP
```

Пример ответа:

```text
[I2C] SCAN: 41 44
```

Если ни одно устройство не ответило:

```text
[I2C] SCAN: NONE
```

Scan выполняется программно через open-drain GPIO. На время scan аппаратный
I2C-контроллер отсоединяется, после завершения создаётся заново. Такой scan
используется потому, что `i2c_master_probe()` в применяемой версии ESP-IDF
может неограниченно ожидать освобождения BUSY после NACK.

Каждый адрес проверяется один раз. Одиночный ACK означает найденное
устройство.

### Чтение регистра

```text
R <addr> <reg> <len>
```

Модуль выполняет одну combined-транзакцию:

```text
START
address + W
reg
REPEATED START
address + R
len байтов
STOP
```

`len` — количество байтов, а не количество регистров.

Пример чтения двух байтов регистра `0x01` устройства `0x41`:

```text
R 41 01 2
```

Ответ:

```text
[I2C] R 41 01: FB 68 OK
```

Команда не знает ширину регистра конкретного устройства. Запрашивать нужно
ровно столько байтов, сколько определено документацией микросхемы.

### Запись регистра

```text
W <addr> <reg> <data...>
```

На шину передаётся один пакет:

```text
START → address + W → reg → data... → STOP
```

Пример записи `0x12AB` в регистр `0x02` устройства `0x41`:

```text
W 41 02 12 AB
```

Ответ:

```text
[I2C] W 41 02 12 AB OK
```

Порядок байтов задаёт пользователь. Для 16-битного big-endian регистра
сначала передаётся старший байт.

### Чтение без адреса регистра

```text
RR <addr> <len>
```

Выполняется обычное чтение `len` байтов без предварительной записи register
pointer:

```text
START → address + R → data... → STOP
```

Команда нужна для устройств без регистров, FIFO и устройств, которые сохраняют
внутренний register pointer.

Пример:

```text
RR 50 8
```

### Запись без адреса регистра

```text
WW <addr> <data...>
```

Все указанные байты передаются без автоматически добавляемого регистра:

```text
START → address + W → data... → STOP
```

Пример:

```text
WW 3C 00 AF
```

## Пример: INA238

INA238 по адресу `0x41` имеет преимущественно 16-битные регистры. Их нужно
читать по два байта:

```text
R 41 00 2
R 41 01 2
R 41 02 2
```

Типичные ответы после сброса:

```text
[I2C] R 41 00: 00 00 OK
[I2C] R 41 01: FB 68 OK
```

Запрос:

```text
R 41 00 3
```

не означает чтение регистров `0x00`, `0x01` и `0x02`. Он запрашивает три
байта из одной транзакции, начатой с register pointer `0x00`. Для
16-битного регистра `0x00` INA238 определены только первые два байта;
значение третьего байта использовать нельзя.

Исключение — 24-битный регистр `POWER` по адресу `0x08`:

```text
R 41 08 3
```

Для чтения нескольких регистров необходимо отправить отдельную команду `R`
для каждого register pointer.

## Ответы и ошибки

Все ответы имеют префикс `[I2C]`.

| Ответ | Значение |
|---|---|
| `OK` | Транзакция завершена |
| `SCAN: NONE` | На адресах `0x03`–`0x77` нет ACK |
| `NACK_ADDR` | Устройство не подтвердило адрес |
| `TIMEOUT` | Транзакция не завершилась за заданное время или SCL удерживается низким |
| `ERR syntax` | Ошибка формата команды или диапазона параметра |
| `MASTER START ERR` | Не удалось захватить GPIO или создать I2C_NUM_1 |

После timeout модуль выполняет физическое восстановление шины:

1. удаляет аппаратный I2C bus;
2. освобождает SDA;
3. выдаёт до девяти импульсов SCL;
4. формирует STOP;
5. заново создаёт I2C_NUM_1.

Если SCL удерживается внешним устройством низким, recovery завершается
ошибкой по ограниченному timeout и не зависает бесконечно.

## Ограничения

- Поддерживаются только 7-битные адреса.
- `reg` имеет размер один байт.
- `len` находится в диапазоне 1–32 байта.
- Terminal не знает карту и ширину регистров подключённого устройства.
- Автоматического чтения последовательных register pointer нет.
- PEC/CRC автоматически не добавляется и не проверяется.
- Режим не предназначен для подключения к активной multi-master шине.
- При выходе из I2C Master текущая последовательность команд отменяется.

## Программный интерфейс

`i2c_master_terminal` вызывается из приложения:

```c
i2c_master_terminal_init();
i2c_master_terminal_configure(mode);
i2c_master_terminal_input_char(ch);
i2c_master_terminal_update(state);
```

`i2c_aux_bus` предоставляет операции:

```c
i2c_aux_bus_init();
i2c_aux_bus_start();
i2c_aux_bus_stop();
i2c_aux_bus_scan(...);
i2c_aux_bus_transmit_receive(...);
i2c_aux_bus_receive(...);
i2c_aux_bus_transmit(...);
i2c_aux_bus_recover_lines();
i2c_aux_bus_reset_controller();
```

Вызывать аппаратные функции I2C_NUM_1 напрямую из других модулей не следует.
Владельцем handle и GPIO является `i2c_aux_bus`.
